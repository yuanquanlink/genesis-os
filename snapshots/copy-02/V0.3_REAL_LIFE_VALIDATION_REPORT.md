# Genesis OS v0.3 Real Life Validation Report

Date: 2026-08-07 (Asia/Shanghai)

## Scope

This pass validates the existing v0.2 P0-P4 system for sustained personal use. It does not add a new Agent, product area, or automatic authority over Goal, Ability, Evidence, Strategy, Mission, or Memory.

## Validated Loop

```text
Raw user input -> Knowledge -> Memory Candidate -> user confirmation
  -> approved Strategy -> Mission Candidate -> user confirmation
  -> Morning Brief -> Daily Plan Candidate -> user confirmation
  -> Mission completion / Evening Reflection -> pending Evidence Candidate
  -> explicit Evidence approval -> Growth Graph snapshot
```

The Day 1 to Day 30 fixture replays this sequence deterministically. It verifies that confirmed Memory, approved Strategy, Active Mission, approved Daily Plan, completed Mission, raw reflection, and pending Evidence remain linked without an automatic Ability change.

## Improvements

- Added migration `0029_mentor_source_details.sql`. Every newly saved Deep Mentor analysis now preserves the Context source ID, source text, source kind, timestamp, confidence, and an explicit unresolved marker when metadata cannot be resolved.
- Mentor UI now renders those source details under `Sources and limits`, so recommendations can be inspected rather than treated as unsupported chat output.
- Data Integrity inspection now identifies confirmed Memory backed by a non-approved candidate and completed Mission records with no linked Evidence. These are report-only formal provenance warnings; repair never mutates formal data.
- Added a longitudinal validation test for the complete approval-gated daily loop and strengthened Mentor / data-integrity regression tests.

## Findings And Resolution

| Finding | Resolution |
| --- | --- |
| Historical Mentor records exposed source IDs but not enough metadata to inspect the basis of an action. | Persisted structured source details for new analyses and rendered them responsively. Older records remain readable and show their existing source IDs. |
| Integrity preview did not distinguish a Strategy provenance warning from a Mission warning and did not inspect confirmed Memory provenance. | Correct entity typing and expanded read-only checks. |
| A completed Mission without an Evidence relation could look like delivery progress. | It is now a visible, non-repairable provenance warning rather than being silently trusted. |

## Known Limits

- The 30-day flow is a deterministic time-compressed validation fixture, not a claim that thirty calendar days of real human activity have already been observed.
- Genesis remains a local, single-user SQLite application. It is not a public multi-user deployment.
- There is no continuous background scheduler. Daily and proactive output is generated on open or explicit request.
- Provider timeout, quota, latency, and quality remain external dependencies. Failures are redacted telemetry and a labelled fallback, never Growth Evidence.
- Existing Mentor analyses created before migration `0029` do not gain historical source snapshots retroactively.

## Next Planning Recommendation

Operate the current system with real records for several weeks before adding capability. Review Usage Dashboard trends, Data Integrity previews, pending-candidate aging, provider failures, mission completion, and whether approved Evidence produces meaningful Growth Graph changes. A future v1.0 plan should prioritize a production authentication, persistence, backup, and scheduling boundary rather than another intelligence module.
